# ถึงหัวหน้า GPT: ไอเดียที่ทดลองสำเร็จแล้ววันนี้ — ขอกระจายงานให้ทีมออกแบบ (เสนอเจ้าของก่อน) และทีมวิศวกรรม
8 ก.ย. 2569 17:00 · จาก C · เจ้าของสั่ง: "นำไอเดียที่ทดลองสำเร็จส่งให้หัวหน้า GPT ไปกระจายงานให้ทีมทำต่อ ทั้งการออกแบบหน้าตา (ขายพี่ก่อน) และระบบวิศวกรรม"
ทุกข้อด้านล่าง **ทำงานได้จริงแล้วบนเว็บ/Mac mini** — งานของทีมคือทำให้ดีบนมือถือ ไม่ใช่สร้างใหม่ · กติกาธุรกิจ/สูตรเงินยังอยู่ฝั่งเซิร์ฟเวอร์ที่เดียว

## A. รวมบัตร+ใบขับขี่ลง A4 พร้อมลายน้ำ — deployed แล้ว (`/documents/a4?bookingId=N`)
พิสูจน์: ดึงรูปจากคลังหลักฐานของใบจอง · ลายน้ำทแยง 3 เส้น 28% ปรับได้ 5–45% (กติกาจากแอป BLURR ของเจ้าของ) · ปรับสว่าง/คอนทราสต์/ขนาด/หมุน/ลาก · พิมพ์หรือ Save as PDF · audit ใครพิมพ์
- **ออกแบบ (ขายเจ้าของก่อน)**: หน้ามือถือ "ก่อนพิมพ์" 1 หน้าจอ: ตัวอย่างกระดาษ + ปุ่มใหญ่ "แชร์ PDF" + ตัวปรับซ่อนใต้ "ปรับภาพ" · สถานะเมื่อรูปยังไม่มี · คำเตือน PDPA แบบไม่ตัน
- **วิศวกรรม native**: วาดด้วย CoreGraphics ตามค่าคงที่เดียวกับ `lib/document-sheet.ts` (A4 2480×3508 · บัตร 1011×638 · ลายน้ำ atan2 3 เส้น · เพดานตัวอักษร min(W,H)×0.085) · เรียก `POST /api/documents/a4` ก่อนแชร์ทุกครั้ง
- บทเรียนที่ต้องล็อกด้วยเทสต์: วาดต้องไม่พึ่งเฟรมของหน้าจอ (แท็บ/แอปอยู่เบื้องหลังแล้วได้กระดาษขาว — เจอจริงวันนี้)

## B. ตาอ่านบัตร — ด่านตรวจตัวเดียว 3 ทาง (เว็บ · Mac · มือถือ)
พิสูจน์วันนี้: Apple Vision บน Mac mini อ่านไทยได้จริง (revision 3 มี th-TH) → ส่งข้อความเข้า `readCustomerDocumentsFromText` ได้ 6 ช่อง + สถานะ ✅/⚠️/❌ · ฝั่งมือถือใช้เส้นเดียวกัน `POST /api/assistant/read-document` โหมด JSON (deployed แล้ว ไม่ต้องมี key)
- **ออกแบบ**: การ์ด 6 ช่องพร้อม 3 สถานะ (ห้ามมี %) · ช่อง ❌ ต้องเด่นว่า "พิมพ์เอง" · วันหมดอายุใบขับขี่ไม่มีวันขึ้น ✅ จากรูปเดียว ต้องมีปุ่ม "ดูรูปเทียบ"
- **วิศวกรรม native**: Vision บนเครื่อง → ข้อความ → API · กับดักที่ C เจอบน Mac (น่าจะเหมือนกันบน iOS): ปิด `usesLanguageCorrection` (ไม่ให้เดาแก้เลขบัตร) · แปลงรูปเป็น sRGB 8-bit ตั้งตรงตาม EXIF ก่อน · Vision ล้มสุ่มได้ ต้อง retry 3 รอบ · วันที่ส่ง API เป็น ค.ศ. เสมอ

## C. สัญญาออกอัตโนมัติเมื่อข้อมูลครบ — ทำงานอยู่บน Mac mini แล้ว
พิสูจน์: ตัวเฝ้าทุก 2 นาที ดูใบจองที่จะรับรถใน 30 วัน ถ้าครบ (ชื่อ เบอร์ เลขบัตร ที่อยู่ ใบขับขี่+วันหมดอายุ ทะเบียนมีจังหวัด ยอดเงิน) → ออก PDF 4 หน้าเอง คำนวณยอดซ้ำก่อนออก · วันนี้ออกจริง 2 ใบ · ใบที่ขาดจะบอกรายช่อง
- **ออกแบบ**: ในใบจองบนมือถือมีแถบ "สัญญา": `รอข้อมูล (ขาด 3 ช่อง: …)` → `ออกแล้ว · ดู/แชร์` · ปุ่มเติมช่องที่ขาดจากตรงนั้นเลย · แจ้งทีมเมื่อออกสัญญา
- **วิศวกรรม (ฝั่ง C จะทำเมื่อเจ้าของสั่ง)**: (1) API "ความพร้อมของสัญญา" ต่อใบจอง = รายการช่องที่ขาด (ใช้ lib เดียวกับตัวเฝ้า) (2) ทางอัปโหลด PDF กลับเข้าใบจองที่มี audit (หมวดเอกสาร `contract`) (3) แจ้ง LINE 1 บรรทัดเมื่อออก — native รอ 2 ตัวนี้ก่อนค่อยต่อ

## D. ทีมกดยอมรับคำขอ Login จากกระดิ่ง — deployed แล้ว
- **ออกแบบ**: การ์ดคำขอในกระดิ่งมือถือ ปุ่มเดียว "กดยอมรับให้เข้าใช้" · บอกชัดว่าบัญชีใหม่ได้แค่ "ดูคิว" จนเจ้าของยกสิทธิ์

## 1) ส่วนแบ่งเจ้าของรถ (พาร์ทเนอร์) — `lib/partner-share.ts`

รถบางคันไม่ใช่ของ DNA EV แต่เป็นของพาร์ทเนอร์ที่เอามาให้ปล่อยเช่า
DNA EV เป็นคนหาลูกค้า ส่งรถ ล้างรถ ดูแลเอกสาร

### สูตร (เจ้าของยืนยันเอง 20 ส.ค. 69)
```
กำไรก่อนแบ่ง   = รายรับทั้งหมด − ค่าใช้จ่ายทุกอย่างที่ไม่ใช่ส่วนแบ่ง
ส่วนของพาร์ทเนอร์ = กำไรก่อนแบ่ง × (percent / 100)      ← ถ้ากำไรก่อนแบ่ง > 0 เท่านั้น
กำไรจริงของ DNA EV = กำไรก่อนแบ่ง − ส่วนของพาร์ทเนอร์
```

### 4 กติกาที่ผิดแล้วจ่ายเงินจริง
1. ⛔ **แบ่งจาก "กำไรก่อนแบ่ง" ไม่ใช่ % ของค่าเช่า** — เข้าใจผิดเป็น % ของค่าเช่า = **จ่ายพาร์ทเนอร์เกินทุกเดือน**
   (ค่าส่งรถ ค่าจ้างคนขับ ค่าล้าง ค่าชาร์จ ค่างวด ต้องหักออกก่อน)
2. ⛔ **ขาดทุนไม่แบ่ง** — กำไรก่อนแบ่งติดลบ → พาร์ทเนอร์ได้ **0** และ DNA EV รับขาดทุนเต็ม
   (กันไม่ให้ระบบคิดว่าพาร์ทเนอร์ "ติดหนี้" เราจากเดือนที่ขาดทุน)
3. ⛔ **ยอดที่ทีมพิมพ์เอง (manual) ชนะเสมอ** — `resolveOwnerShare()` คำนวณจาก `cars.owner_share_pct`
   **เฉพาะใบที่ไม่เคยกรอก** · ห้ามเขียนทับประวัติ
4. ⛔ **ที่ลงฐานเป็นยอดบาทเสมอ** (`bookings.owner_share`) — ปุ่ม % บนจอเป็นแค่เครื่องคิดเลข
   แก้ค่าใช้จ่ายทีหลัง **ยอดที่บันทึกไว้จะไม่ขยับเอง**

`normalizePartnerPercent()` หนีบค่าไว้ 0–100 เสมอ · โหมดช่องบนจอ: `"baht"` (ค่าเริ่มต้น) หรือ `"percent"`
⚠️ หน้าจองใหม่กับหน้าแก้ไขใบจองต้องเรียก `ownerShareFromInput()` **ตัวเดียวกัน** — มีเทสต์นับจุดเรียกว่าต้องเป็น **2 พอดี**
⚠️ ส่วนแบ่ง + กำไรบริษัท ต้องเท่ากำไรก่อนแบ่งเสมอ — เงินห้ามหายจากการปัดเศษ (`round2` ทุกจุด)

### ของจริงในฐาน
| รถ | % พาร์ทเนอร์ |
|---|---|
| carId 62 (Geely EX2 Max) | 50% |
| carId 65 (Geely EX2 Max) | 50% |
| carId 66 (Geely EX2 Max) | 50% |
| carId 68 (Ora 5) | **75%** |
| อีก 9 คัน | 0% (ของ DNA EV เอง) |

🟡 **ใบจองที่มี `owner_share > 0` มีแค่ 4 ใบจาก 109** (3 ใบ `returned` · 1 ใบ `completed`)
ทั้งที่รถพาร์ทเนอร์ 4 คันถูกเช่าไปมากกว่านั้นแน่นอน
→ ที่มาของกติกาข้อ 3: `owner_share_pct` **เคยมีในฐานแต่ไม่มีโค้ดอ่าน** ทีมกรอกเองได้แค่ 3 จาก 58 ใบ
= หนึ่งในเหตุที่กำไรเคยสูงเกินจริง · ตอนนี้ระบบคำนวณ auto ให้แล้วเมื่อใบไม่ได้กรอก
→ **สำหรับดีไซน์**: จอใบจองของรถพาร์ทเนอร์ต้องโชว์ให้เห็นว่าใบนี้ใช้ยอด `manual` หรือ `auto`
(`resolveOwnerShare()` คืน `source: "manual" | "auto"` มาให้แล้ว — เอาไปขึ้นป้ายได้เลย)

## 3) 🔴 กำไรมี **สองบรรทัด** และตอนนี้บรรทัดแรกยังเชื่อไม่ได้

`lib/secretary-history.ts` แยกไว้ชัดเจน — ห้ามเอามาทับกัน:

| บรรทัด | หักค่างวดจากไหน | ความหมาย | สถานะจริงวันนี้ |
|---|---|---|---|
| `profit` | ค่างวดที่**มีสลิปยืนยันแล้ว** (`financial_evidence` `category='installment'` `status='confirmed'`) | กำไรตามบัญชี | 🔴 **สลิปค่างวดในฐาน = 0 ใบ** → ไม่มีค่างวดถูกหักเลย |
| `profitAfterPlannedInstallments` | **ค่างวดตามแผน** (`car_costs` `kind='installment'`) | ภาพจริงของธุรกิจ | ✅ ใช้ได้ |

```
installmentsCharged = max(installments, plannedInstallments)   ← กันนับซ้ำตอนเริ่มแนบสลิปจริง
profitAfterPlannedInstallments = revenue − (feeExpenses + transactionExpenses + ownerShare + installmentsCharged)
```

**คอมเมนต์ในซอร์สเขียนไว้ตรง ๆ**: *"ตอนนี้ financial_evidence ยังว่าง ทำให้กำไรตามบัญชีสูงเกินจริง (margin 93% ซึ่งเป็นไปไม่ได้สำหรับธุรกิจเช่ารถ)"*

→ **สำหรับดีไซน์**: จอสรุปเงินของแอปมือถือ **ห้ามโชว์ `profit` เดี่ยว ๆ**
ต้องโชว์ `profitAfterPlannedInstallments` เป็นตัวเด่น หรือโชว์คู่กันพร้อมป้ายว่าบรรทัดบนยังไม่หักค่างวดที่ยังไม่มีสลิป
→ **กติกาที่บ้านนี้ยึด**: *margin สูงผิดปกติ = มีบั๊ก ไม่ใช่ข่าวดี* — ธุรกิจเช่ารถจริงไม่มีทางกำไร 90%+
เจอเมื่อไรให้ไล่หาว่าต้นทุนตัวไหนหาย (ที่ผ่านมาคือค่างวดกับค่าจ้าง)

## 4) สูตรกำไรเต็มของธุรกิจนี้ — เรียงตามลำดับการหัก

```
รายรับ          = ค่าเช่า (total_price) + booking_fees[income] + transactions[income หลังตัดสำเนา]
− ค่าใช้จ่ายงาน  = booking_fees[expense] + transactions[expense หลังตัดสำเนา]
= กำไรก่อนแบ่ง
− ส่วนแบ่งพาร์ทเนอร์ (คิดจากกำไรก่อนแบ่ง · ขาดทุนไม่แบ่ง)
− ค่างวดรถ (ตามแผน หรือตามสลิปที่ยืนยัน — ยึดตัวที่สูงกว่า)
= กำไรจริงของ DNA EV
```

**นับเฉพาะใบที่ปิดแล้ว** (`completed` / `returned`) สำหรับกำไรจริง ·
ใบที่ยังไม่ปิดไปอยู่ใน "คาดการณ์" (`monthlyProfitForecast`) โดยตัด `cancelled` และ `rejected` ทิ้ง

**ค่าใช้จ่ายที่ไม่ผูกใบจอง** ก็ถูกนับด้วย — `transactions` ที่ `booking_id IS NULL AND type='expense' AND is_passthrough=0`
(หลังตัดสำเนา) รวมเข้าหมวดค่าใช้จ่ายของเดือนนั้น

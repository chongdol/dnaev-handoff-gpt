## 2. ราคาเช่าจริง (ยืนยันจากโปสเตอร์ที่เจ้าของอนุมัติแล้ว)

| ช่วงวันเช่า | ราคา/วัน |
|---|---|
| 1–2 วัน | 1,700 |
| 3–6 วัน | 1,500 |
| 7–14 วัน | 1,300 |
| 15–29 วัน | 1,150 |
| **30 วันขึ้นไป (รายเดือน)** | **1,000** |

- **มัดจำจองคิว 1,500 บาท**
- ติดต่อในโปสเตอร์: LINE `@DNAEV` + เบอร์โทร 2 เบอร์ (เบอร์จริงไม่ใส่ในเอกสารสาธารณะนี้)

📌 **ข้อสังเกตที่ยืนยันสมมติฐานของฝั่งเรา**: ช่วงวันในโปสเตอร์ (1–2 / 3–6 / 7–14 / 15–29 / 30+)
ตรงกับ **ขั้นบันไดตั้งต้น 5 ขั้นที่ระบบเติมให้อัตโนมัติ**ในฟอร์มเพิ่มรถพอดี ไม่ต้องแก้ช่วงวันเอง
ทีมกรอกแค่ราคา 5 ช่อง — ถือว่าช่วงวันชุดนี้เป็น **มาตรฐานของธุรกิจ** ใช้ออกแบบหน้าจอได้เลย

**กติกาแสดงราคาที่ต้องรักษาไว้ทุกหน้าจอ** (บ้านหลังเดียวคือ `lib/rental-pricing.ts`):
- เลขตัวเด่น = ราคาของ **ช่วงวันที่ลูกค้าเลือกจริง** เท่านั้น (เพราะเป็นยอดที่จะเก็บจริง)
- เลขตัวรอง = ราคาถูกสุด **พร้อมเงื่อนไขว่าต้องเช่ากี่วันขึ้นไป** — ห้ามโชว์ "เริ่มต้น 1,000" ลอย ๆ
  เพราะกลายเป็นโฆษณาราคาที่ลูกค้าเช่าสั้นไม่ได้จริง (เคยเกิดแล้วกับ Denza D9)
- ถ้าช่วงที่เลือกอยู่ในขั้นถูกสุดแล้ว ให้ซ่อนบรรทัดรอง จะได้ไม่โชว์เลขซ้ำสองที่

## 3. ของใหม่ในระบบ: ช่องทาง "เพิ่มรถเข้าคลัง" (มีเป็นครั้งแรก)

เดิม `POST /api/cars` รับได้อย่างเดียวคือเปลี่ยนสี/รูป — **รถทุกคันในคลังถูกใส่ลงฐานด้วยมือ
ไม่เคยผ่านหน้าจอ** ทีมจึงเพิ่มรถเองไม่ได้เลย ตอนนี้เขียนเสร็จแล้ว

### สัญญา API

```
POST /api/cars
{
  "action": "create_car",
  "model": "Chery Q Quint",
  "licensePlate": "<ทะเบียน>",     // บังคับ · ห้ามซ้ำ
  "dnaCode": "16",                  // รหัสที่ลูกค้าใช้เรียก → เก็บเป็น "DNA 16 <ทะเบียน>"
  "color": "#7d6085",
  "photoUrl": "/cars/vehicles/car-16.png",
  "rangeKm": 400,
  "seats": 5,
  "ownerName": "",                  // เว้นว่าง = รถของบริษัทเอง
  "ownerSharePct": 0,               // > 0 ต้องมี ownerName ด้วย
  "notes": "",
  "tiers": [
    { "minDays": 1,  "maxDays": 2,    "pricePerDay": 1700 },
    { "minDays": 3,  "maxDays": 6,    "pricePerDay": 1500 },
    { "minDays": 7,  "maxDays": 14,   "pricePerDay": 1300 },
    { "minDays": 15, "maxDays": 29,   "pricePerDay": 1150 },
    { "minDays": 30, "maxDays": null, "pricePerDay": 1000 }
  ]
}
```

**คำตอบ**
- สำเร็จ → `200 { ok: true, carId, warnings: string[] }`
  `warnings` = เรื่องที่ควรรู้แต่ไม่ถึงกับห้ามบันทึก **หน้าจอต้องโชว์หลังบันทึกสำเร็จ**
  (ไม่ได้ตั้งรหัส DNA · ไม่ได้เลือกรูป · ไม่ได้กรอกระยะวิ่ง/ที่นั่ง · ตั้งเจ้าของแต่แบ่ง 0%)
- ข้อมูลไม่ผ่าน → `400 { ok:false, error }` (ข้อความไทยบอกว่าต้องแก้อะไร เอาไปโชว์ตรง ๆ ได้)
- ทะเบียนซ้ำ → `409` พร้อมบอกว่าชนกับรถคันไหน (รวมคันที่ปลดระวางแล้ว → แนะให้เปิดใช้คันเดิมกลับมา)
- ไม่มีสิทธิ์ → `403` (ต้องมีสิทธิ์ระดับ **แก้ข้อมูล** ไม่ใช่แค่ดูใบจองได้)

`GET /api/cars` เพิ่ม `models: string[]` = รายชื่อรุ่นที่มีอยู่แล้วในคลัง
→ ฟอร์มต้องให้เลือกจากรายการนี้ก่อนเสมอ **เพราะระบบจับคู่รถกับใบจองด้วยชื่อรุ่น สะกดต่าง = จับคู่ไม่ติด**
(ของจริงตอนนี้มีรุ่นเดียวกันสะกดปนกัน 3 แบบอยู่แล้ว อย่าให้เพิ่มอีก)

### กติกาที่หลังบ้านบังคับไว้ (หน้าจอไม่ต้องคิดซ้ำ แต่ต้องเข้าใจเพื่อวาง error ให้ถูกที่)

1. **ขั้นบันไดราคาห้ามมีรู** — ต้องเริ่มวันที่ 1 · ต่อกันพอดี (`ขั้นก่อนหน้าจบวันที่ 6 → ขั้นถัดไปเริ่มวันที่ 7`) ·
   ขั้นสุดท้ายต้องเปิดปลาย (`maxDays: null`) · ราคาต้อง > 0
   *เหตุผล*: ช่วงวันที่ไม่มีขั้นครอบจะถูกคิด **ราคาแพงสุด**เงียบ ๆ ลูกค้าโดนเรตผิดโดยไม่มีใครรู้
2. **ราคาแพงขึ้นเมื่อเช่านานกว่า = เตือน ไม่บล็อก** (อาจตั้งใจ) → เข้า `warnings`
3. **เทียบทะเบียนซ้ำแบบตัดรูปแบบการพิมพ์ทิ้งก่อน** — "DNA 5 7ขน4945" กับ "7ขน 4945" ถือเป็นคันเดียวกัน
4. **รถป้ายแดง** (ทะเบียนไม่มีตัวเลข) ระบบไม่เอาไปตัดสินว่าซ้ำ ปล่อยให้ unique index ของฐานกันชั้นสุดท้าย
5. **รหัส DNA ไม่กรอกก็บันทึกได้ แต่ลูกค้าจะเห็นแค่รุ่นกับสี** — ระบบ **ห้ามเดาเลขให้เอง**
   (เลข DNA คือเลขที่ทีมใช้คุยกับลูกค้าจริง เดาผิด = คุยกันคนละคัน)
6. **รูปรถ**: มีให้เลือก 16 แบบ · ไม่เลือก = ระบบเดารูปจากรุ่น/สี ซึ่งรุ่นใหม่จะตกไปที่รูปมาตรฐาน
   → ลูกค้าเห็นรูปผิดคัน · ระบบเตือนแต่ไม่บล็อก
7. **ชื่อสีไทย** มาจากตาราง 26 สีใน `lib/car-colors.ts` — รหัสสีที่ไม่อยู่ในตารางจะทำให้การ์ดรถ
   **ไม่โชว์ชื่อสี** ฟอร์มจึงเตือนตั้งแต่ตอนกรอก และมีชุดสีมาตรฐานให้เลือก
8. ทุกครั้งที่เพิ่มรถ ระบบจด `audit_log` + เด้งแจ้งเจ้าของอัตโนมัติ · เขียนราคา/audit ไม่ผ่าน = **ถอนรถออก**
   ไม่ปล่อยรถที่ไม่มีราคาค้างในคลัง

## 4. สิ่งที่อยากให้ออกแบบรอไว้

**ก. ฟอร์ม "เพิ่มรถเข้าคลัง" เวอร์ชันมือถือ/iPad**
ตอนนี้ทำเป็นโมดัลบนเว็บ (ใช้ได้ทั้ง 375px และ 1280px วัด DOM แล้ว) แต่ยังเป็นฟอร์มยาวธรรมดา
สิ่งที่อยากได้จากฝั่งดีไซน์:
- ลำดับขั้นที่เหมาะกับการยืนกรอกหน้ารถจริง (ถ่ายรูป → ทะเบียน → ราคา ?)
- ตารางขั้นบันได 5 ขั้นบนจอแคบ — ตอนนี้เป็น 3 ช่องต่อแถว (ตั้งแต่วัน / ถึงวัน / บาทต่อวัน) + ปุ่มลบ
  ถ้ามีท่าที่ดีกว่านี้ (เช่นให้ช่วงวันเป็นค่าตายตัว 5 ขั้นแล้วกรอกแค่ราคา) เสนอมาได้ — **หลังบ้านรองรับทั้งสองแบบ**
- ที่วางคำเตือน (`warnings`) หลังบันทึกสำเร็จ ให้ทีมเห็นแล้วอยากกลับไปแก้ ไม่ใช่กดผ่าน

**ข. การ์ดรถ + หน้าเช่าของ Chery Q**
- รุ่นนี้เป็นรถ **ราคาถูกที่สุดในคลัง** (รายเดือน 1,000/วัน) กลุ่มลูกค้าต่างจาก Denza D9 ชัดเจน
- อยากได้ท่าโชว์ "ยิ่งเช่านาน ยิ่งถูกลง" ที่ลูกค้าเข้าใจใน 1 วินาที โดยไม่ผิดกติกาข้อ 2 ด้านบน
- โทนม่วงลาเวนเดอร์ของโปสเตอร์กับธีมแอปปัจจุบัน (น้ำเงินเข้ม/ส้ม) ต้องอยู่ด้วยกันได้

**ค. หน้าจอที่ยังไม่มีเลย: แก้ข้อมูลรถ / ปลดระวางรถ**
เพิ่มรถได้แล้ว แต่ **แก้ทะเบียน แก้ราคา ปลดระวาง ยังทำในแอปไม่ได้** (แก้ได้แค่สีกับรูป)
ถ้าออกแบบเผื่อไว้ตอนนี้ ฝั่งหลังบ้านจะเขียน endpoint ตามได้เลย

## 5. ข้อควรระวังสำหรับฝั่งดีไซน์

- **ทะเบียนจริงเป็นข้อมูลลับของธุรกิจ** — หน้าจอฝั่งลูกค้าเห็นได้แค่ "DNA n" ถ้าไม่มีรหัสให้โชว์แค่รุ่นกับสี
  ห้ามออกแบบหน้าลูกค้าที่มีช่องทะเบียน · ชื่อเจ้าของรถ (รถหลายคันเป็นของผู้ร่วมหุ้น)
- ราคาในเอกสารนี้เป็นราคาที่ **ประกาศขายจริงแล้ว** ใช้ทำ mockup ได้ตรง ๆ ไม่ต้องใส่ตัวเลขสมมติ
- รถคันนี้ยังไม่เข้าฐานจริง — ระหว่างออกแบบให้ใช้เป็นข้อมูลตัวอย่างได้ แต่อย่าอ้างว่ามีในระบบแล้ว

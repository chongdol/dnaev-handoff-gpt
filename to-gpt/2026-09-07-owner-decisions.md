# เจ้าของเคาะแล้ว (7 ก.ย. 2569 ค่ำ) — หลักการ "อัตโนมัติก่อน แก้ทีหลัง" + ตัวอย่างปิดจ๊อบคืนเงินประกัน

อ่านคู่กับ `2026-09-07-review-booking-details.md` — ไฟล์นี้ตอบข้อ 9 ข้อ 5 ของไฟล์นั้น และตั้งกติกาใหม่ที่มีผลกับทุกหน้าจอ

## 1. คำสั่งเจ้าของ (เรียบเรียง)

> ต้องทำให้ง่าย — อะไรที่ทีมไม่เคยใช้ ไม่เคยกด ให้ระบบ**คิดให้อัตโนมัติ**
> เช่น โอนคืนเงินประกันลูกค้า: ระบบลงส่วนที่หักลูกค้าให้ว่ามีอะไรบ้าง แล้ว**ปิดจบจ๊อบให้ทันที**
> ถ้ามีผิด เจ้าของ**กด "แก้ไข" ให้ตรงได้ทุกครั้ง** · ปิดจ๊อบแล้ว**เด้งข้อความเตือนทีมในแชต**

## 2. กติกาใหม่ที่ทุกหน้าจอต้องยึด (เพิ่มเป็นหลักการข้อ 11 ของก้อนหนึ่ง)

| กติกา | หมายถึงในดีไซน์ |
|---|---|
| **ค่า default ต้องเป็นคำตอบที่ถูกใน 80% ของเคส** | ทุกช่องมีค่าเสนอจากระบบ/คลัง/รูป — คนแค่กวาดตาแล้วแตะ ไม่ใช่กรอกจากศูนย์ |
| **ปิดจ๊อบ = แตะเดียว** | "ส่งแล้ว" "รับคืนแล้ว" "โอนคืนแล้ว" เป็นปุ่มเดียวบนการ์ดงาน ไม่มีหน้าฟอร์มคั่น · หน้าสรุป/หัก **โผล่หลังปิด** ไม่ใช่ก่อน |
| **ไม่มี gate ที่บล็อก มีแต่เตือน** | ปล่อยรถโดยลูกค้ายังไม่กดลิงก์ยืนยัน / มัดจำยังไม่ครบ / สลิปยังไม่ยืนยัน → ทำได้ แต่การ์ดขึ้นป้ายเหลืองบอกว่าอะไรยังค้าง (ตอบข้อ 9.5 ของไฟล์ก่อน: **เปลี่ยน gate เป็นเตือน**) |
| **แก้ได้ทุกเมื่อ ทุกช่อง** | ปุ่ม "แก้ไข" อยู่บนทุกใบทุกสถานะ (เจ้าของและทีมที่มีสิทธิ์) · แก้แล้วระบบคำนวณใหม่ + จด audit + เด้งบอกทีมอีกครั้งว่า "แก้จาก x เป็น y" |
| **ปิดแล้วเด้งบอกทีม** | ทุกการปิดจ๊อบ (ส่งแล้ว/รับคืน/โอนคืนประกัน/รับเงิน) ส่งข้อความสรุป 1 ข้อความเข้า **กล่องเตือนในแอป + push มือถือ** และ **กลุ่ม LINE ทีม** (จนกว่า push จะพร้อม) — ข้อความบอกตัวเลขที่ระบบคิดให้ เพื่อให้ทีมทักได้ถ้าผิด |
| **ฟีเจอร์ที่ไม่มีใครกด = ซ่อนหรือทำให้อัตโนมัติ** | ลิงก์ให้ลูกค้ากดยืนยัน (ใช้ 2/108) → ย้ายไปเป็นทางเลือกในเมนู ไม่ใช่ขั้นบังคับ · ยืนยันสลิป (ค้าง 59/60) → ระบบเสนอยอดจากรูป คนแตะรับ · เปลี่ยนสถานะ → หายไปเลย เกิดจากงาน |

## 3. ตัวอย่างที่เจ้าของยก — ปิดจ๊อบ "รับรถคืน + คืนเงินประกัน" แตะเดียว

### 3.1 หน้าจอ (ลำดับที่ควรเป็น)
```
การ์ดงาน "รับคืน · DNA 3 · คุณตัวอย่าง · วันนี้ 10:00"
  ▸ ปุ่มใหญ่: [รับคืนแล้ว ✓]

→ แตะแล้ว ระบบคิดให้ทันที (ไม่ต้องเปิดฟอร์ม):
  ┌ ปิดจ๊อบ #9001 ─────────────────────────────┐
  │ เงินประกัน                       ฿6,000     │
  │ หัก: ค่าชาร์จไฟ 30% × ฿5           −฿150   │  ← จาก % แบตตอนส่ง vs ตอนคืน (ถ่ายหน้าปัดตอนคืน ตาอ่าน %)
  │ หัก: คืนช้า 0 ชม.                    ฿0     │  ← จาก end_at vs เวลาที่แตะ
  │ หัก: วิ่งเกิน 0 กม.                  ฿0     │  ← ถ้ามีเลขไมล์
  │ หัก: ความเสียหาย                      ฿0     │  ← ต้องคนใส่ (ถ่ายรูปแนบ)
  │ ────────────────────────────────────────  │
  │ ต้องคืนลูกค้า                    ฿5,850     │
  │ บัญชี: (ยังไม่มี — ถ่ายหน้าบัญชี / เลือกจากใบก่อน) │
  │ [โอนคืนแล้ว ฿5,850]        [แก้ไขตัวเลข]  │
  └────────────────────────────────────────────┘

→ แตะ "โอนคืนแล้ว" (หลังโอนจริง):
  • ใบจอง → returned · เงินประกันปิด · transactions/หักลงฐาน · audit
  • เด้งทีม: "ปิดจ๊อบ #9001 DNA 3 · คืนประกัน ฿5,850 (หักค่าชาร์จ ฿150) · โดย พนักงาน ก"
  • ปุ่ม [แก้ไข] ยังอยู่บนใบตลอด — แก้แล้วเด้งซ้ำ "แก้ #9001: หัก ฿150 → ฿350 (เพิ่มค่าล้าง)"
```

### 3.2 ตัวเลขมาจากไหน (ระบบคิด · คนไม่ต้องพิมพ์)

| รายการหัก | สูตร | อินพุตที่ต้องมี | วันนี้ในระบบ | สถานะ |
|---|---|---|---|---|
| ค่าชาร์จไฟ | (% แบตตอนส่ง − % ตอนคืน) × อัตราต่อ % ของรุ่น (EX2 5 บ./% · รุ่นอื่น 7 บ./%) | % แบตตอนส่ง (ถ่ายหน้าปัดตอนส่ง) · % ตอนคืน | มีช่อง `customer_charging` ให้พิมพ์ยอดเอง · อัตราอยู่ในสคริปต์สัญญา ไม่อยู่ในฐาน | 🔴 เพิ่มช่อง % แบต 2 จุด + อัตราลง `cars` — หลังบ้านทำ |
| คืนช้า | ชั่วโมงเกิน `end_at` × อัตรา (เจ้าของกำหนด) | เวลาที่แตะ "รับคืนแล้ว" | ไม่มี | 🔴 ต้องเจ้าของบอกอัตรา/ผ่อนผันกี่นาที |
| วิ่งเกิน | (กม. คืน − กม. ส่ง − ระยะที่ให้) × อัตราของรุ่น (10/12/15 บ./กม.) | เลขไมล์ 2 จุด · ระยะที่ให้ต่อวัน | ไม่มีช่องเลขไมล์ | 🔴 เพิ่มช่อง 2 จุด (ตาอ่านจากรูปหน้าปัดได้) |
| ความเสียหาย | คนใส่ยอด + รูป | — | มีช่อง `return_damage` | ✅ |
| ค่าล้าง | default 0 (ให้เจ้าของเคาะว่ามีค่ามาตรฐานไหม) | — | มีช่อง `return_cleaning` | ✅ |
| ต้องคืน | `max(0, ประกัน − หักรวม)` · ถ้าหักเกินประกัน = ลูกค้าต้องจ่ายเพิ่ม | — | `securityDepositSettlement()` มีแล้ว มีเทสต์ | ✅ |
| บัญชีปลายทาง | จากใบก่อนของลูกค้าคนเดิม · หรือถ่ายหน้าบัญชีให้ตาอ่าน | — | ช่องมี แต่ว่าง 100% | 🟡 ต้องเสนออัตโนมัติ |

### 3.3 API ที่จะรองรับ (หลังบ้านทำ — GPT ออกแบบหน้าจอตามนี้ได้เลย)

| เครื่องมือ | ส่งอะไร | ระบบทำอะไร | มีแล้ว/ใหม่ |
|---|---|---|---|
| `job.complete(jobId, {batteryPct?, odometerKm?, photos?})` | ค่าที่อ่านจากรูป/พิมพ์ (ทุกตัวไม่บังคับ) | คิดรายการหักทั้งหมด → เขียน `complete_return` (มีแล้ว) → เปลี่ยนสถานะ → คืน "ใบปิดจ๊อบ" ให้โชว์ → เด้งทีม | 🔴 ห่อของเดิม |
| `deposit.refund(bookingId, amount)` | ยอดที่โอนจริง (default = ต้องคืน) | `POST /api/deposits` (มีแล้ว กันคืนเกิน/กดซ้ำ) → ปิดประกัน → เด้งทีม | ✅ + เด้ง |
| `booking.edit(bookingId, patch)` | ช่องที่แก้ | `update_financial_summary` / `update_booking` (มีแล้ว) → คำนวณใหม่ → audit → เด้งทีมว่าแก้อะไร | ✅ + เด้ง |
| `notify.team(event)` | เหตุการณ์ปิด/แก้ | กล่องในแอป + push + LINE กลุ่ม (รวม 1 ข้อความ · ถามโควตาก่อน) | 🔴 |

## 4. ใช้หลักการเดียวกันกับจ๊อบอื่น (ให้ GPT ออกแบบเป็นชุดเดียวกัน)

| จ๊อบ | แตะเดียว | ระบบคิดให้ | ป้ายเตือน (ไม่บล็อก) | เด้งทีม |
|---|---|---|---|---|
| ส่งรถ | [ส่งแล้ว ✓] | เวลาส่งจริง · % แบต/เลขไมล์จากรูปหน้าปัด · สถานะ → active | มัดจำยังไม่ครบ · สลิปค้าง · ลูกค้ายังไม่กดยืนยัน · เอกสารไม่ครบ | "ส่ง DNA 3 ให้คุณตัวอย่างแล้ว 10:05 · ค้าง ฿x" |
| รับเงิน | การ์ดจากสลิป [รับ ฿x ✓] | ยอด/วันที่จากรูป · ก้อนไหนครบ · ยอดค้างใหม่ | ยอดไม่ตรงก้อนไหนเลย | "รับเงิน #9001 ฿x · เหลือ ฿y" |
| ออกสัญญา | [ออกสัญญา] | ดึงทุกช่องจากใบ · ตรวจ 2 สมการ · PDF | ช่องที่ยังขาดสำหรับสัญญา (ทะเบียนไม่มีจังหวัด ฯลฯ) | — |
| สร้างใบจอง | การ์ดข้อเสนอ [ยืนยัน ✓] | ทุกช่อง (ไฟล์ก่อนหน้า ข้อ 4) | ช่องที่อ่านไม่ออก/ขัดแย้ง | "ใบจองใหม่ #9001 …" (มีแล้วเข้ากลุ่ม LINE) |

## 5. ยังรอเจ้าของ (ไม่ขวางการออกแบบ)
- อัตราคืนช้า + ผ่อนผันกี่นาที · ค่าล้างมาตรฐานมีไหม
- ช่องนิติบุคคล (ชื่อบริษัท เลขผู้เสียภาษี) ต้องมีไหม
- "รูปแบบบริการ" บนฟอร์มเก่ายังใช้ไหม (ถ้าไม่ตอบ = ตัดตามหลักการข้อ 2)

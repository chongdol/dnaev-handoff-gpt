⚠️ **ไม่มีภาพแนบรอบนี้** — เครื่องมือฝั่งนี้ไม่มีทางบันทึกภาพหน้าจอที่ถ่ายระหว่างตรวจเป็นไฟล์ได้ในรอบนี้

## ส่วนที่ประกอบแล้ว (deployed = ยัง — พร้อม deploy เมื่อสั่ง)

จอ `/chat` ใหม่ ใช้โครง "กล่องเดียว" ตามภาพ `inbox-top.png`/`inbox-scroll-01.png` เป็นฐาน (สีชุดเดียวกับ /home ที่อนุมัติแล้ว — เลือกยืมโทเคนจาก /home แทนสีในภาพ Simulator ตามที่ข้อ 5 ของใบสั่งงานให้ยึดโทเคนจริง)

1. **สรุปวันนี้** — การ์ดบนสุดเสมอ ข้อมูลจาก `GET /api/home` ล้วน (`day.total/completed/extraAmount/depositAmount` + นับ `jobs[]` แยกตาม kind) ปุ่ม "ดูงานวันนี้" พาไป `/jobs` จริง (ไม่มีปุ่ม "ดูรายการค้าง" เพราะยังไม่มีจอปลายทางจริงให้ไป — ตามกติกาข้อ 3 ที่ให้ระบุรอหลังบ้านแทนแสดงว่าทำได้แล้ว)
2. **ปิดจ๊อบรับคืนรถ** — หนึ่งการ์ดต่อหนึ่งใบจองที่ `kind=return` และยังไม่เสร็จจาก `/api/home` เรียงตามเวลานัด ขยายแล้วดึงยอดประกัน/ยอดคืนจาก `GET /api/bookings` (`.summary`) ผสมกับ inputs (ค่าชาร์จ/ค่าปรับ/อื่นๆ) ผ่าน `securityDepositSettlement()` โชว์ยอดคืนแบบสด กดยืนยันยิง `PATCH /api/bookings {action:"complete_return", deductions, refundPaid}` — เส้นเดียวกับหน้าแก้ไขใบจองของแอปเดิม
3. **คืนเงินประกัน** — หนึ่งการ์ดต่อหนึ่งแถวจาก `GET /api/deposits` (`outstanding[]`) เรียงเลยกำหนดก่อน ขยายแล้วโชว์เงินประกัน/หักแล้ว/โอนแล้ว/บัญชีรับเงินตามสิทธิ์ (`canViewFullRefundAccount` มาจากฝั่งเซิร์ฟเวอร์อยู่แล้ว) ปุ่ม "บันทึกการคืนเงิน" ยิง `POST /api/deposits {bookingId, amount}` — **ปุ่มหายไปเลยถ้า `canRecord=false`** ไม่ใช่แค่ disabled (กันคนเข้าใจผิดว่ากดได้)
4. ช่องพิมพ์ล่างใส่ไว้ตามกรอบภาพ (attach/mic/send) แต่ **ปิดใช้งานจริง** (`cursor:not-allowed`, opacity ลดเฉพาะไอคอน/ข้อความ) ป้าย "ยังไม่เปิดใช้งาน — รอต่อกับระบบตีความข้อความ" — ตรงกับกติกาข้อที่ให้บอกรอหลังบ้านแทนทำเป็นใช้ได้แล้ว (Luna ยังไม่มี route ให้เรียกเลยสักเส้นตามที่ตอบไปในเอกสารก่อนหน้า)

**ไม่ได้ทำรอบนี้ตามที่ระบุไว้แต่ต้น** (ไม่ต้องรอครบ 12 ตามที่อนุญาต): เธรดใบจองแบบเต็ม (ปุ่มต่อวัน/ออกสัญญา) · การ์ดอ่านสลิป/แปลงประโยค/lead — พวกนี้ยังไม่มีหลังบ้านรองรับ ไม่ได้ใส่โครงหลอกไว้เลย

## ช่องว่างที่ต้องรู้ก่อนออกแบบต่อ

- **"ปิดจ๊อบ" มีอยู่สองที่ ความหมายไม่เท่ากัน** — เพิ่งเห็นว่ามีอีกเซสชันประกอบ `/jobs` (`urgent-jobs-v1`) เสร็จไปพร้อมกัน มีปุ่ม "ปิดจ๊อบ" ของตัวเองเหมือนกัน แต่ของ `/jobs` ปิดได้แค่ฝั่งกายภาพ (ส่งรถ/รับคืนจริงหรือยัง — `pickup_done`/`dropoff_done` ผ่าน `/api/urgent-jobs`) **ไม่แตะเงินเลย** ส่วนของ `/chat` ที่นี่คือปิดยอดการเงิน (หัก/คืนประกัน) คนละงานกัน คนละปุ่ม ไม่ชนกันทางเทคนิค แต่ชื่อคล้ายพอจะสับสนตอนออกแบบเธรดใบจองเต็มรูป — ตอนออกแบบ "ปุ่มงาน" ในเธรด ควรแยกคำให้ชัดว่าอันไหนคือ "ยืนยันว่าส่งรถ/รับคืนแล้ว" อันไหนคือ "ปิดยอดเงิน"
- **นามสกุลข้อมูลที่การ์ดต้องใช้จริง**: การ์ดรับคืนใช้ `customer` เป็นชื่อเต็มจากฐาน (ไม่มีช่อง "ชื่อเล่นตามสิทธิ์" แยกต่างหากในทั้ง `/api/home` และ `/api/bookings` ตอนนี้) ถ้าดีไซน์ต้องการนามสกุล/ชื่อเล่นแยกจริง ต้องเพิ่ม column และ route ก่อน ยังไม่มี

## ผลทดสอบ (รันในเครื่อง — DOM จริง ไม่ใช่ภาพ)

ตั้งค่าทดสอบ: ใบจองสังเคราะห์ในเครื่อง 2 ใบ (สมชาย ใจดี / มานี รักเรียน — ชื่อทดสอบมาตรฐานของโปรเจกต์ ไม่ใช่ลูกค้าจริง) แก้ค่าชั่วคราวแล้วคืนค่าเดิมทุกคอลัมน์หลังตรวจเสร็จ

**การ์ดปิดจ๊อบรับคืนรถ** (ใบทดสอบ car=Ora 5 EV, deposit=5000):
```
เงินประกัน ฿5,000 · ยอดคืนตามที่กรอก ฿5,000   ← ตรงฐาน (deductions ทั้งหมด=0)
พิมพ์ "ค่าชาร์จที่หัก" = 800 → ยอดคืนอัปเดตทันทีเป็น ฿4,200   ← ตรงสูตร (5,000-800)
กดปิดจ๊อบด้วยสิทธิ์ viewer (ทดสอบผ่านลิงก์) → error "โหมดทดลองผ่านลิงก์เปิดดูได้
  แต่ต้อง Login ด้วยอีเมลทีมก่อนแก้ข้อมูลจริง"   ← ข้อความจริงจาก guard ฝั่งเซิร์ฟเวอร์
  (พิสูจน์ว่า request ไปถึง /api/bookings จริง ผ่านการตรวจ action ก่อนโดน 403)
```

**การ์ดคืนเงินประกัน** (ใบทดสอบ car=Geely EX2 Max, deposit=6000, คืนแล้ว 1000):
```
เงินประกัน ฿6,000 · ยอดหักแล้ว ฿0 · โอนคืนไปแล้ว ฿1,000
บัญชีรับเงิน: กสิกรไทย · สมชาย ใจดี · 1234567890
→ ทุกช่องตรงกับค่าที่ตั้งไว้ในฐานทุกตัว · ปุ่ม "บันทึกการคืนเงิน" หายไปจริง
  (แสดงข้อความ "บัญชีนี้ไม่มีสิทธิ์บันทึกการคืนเงิน" แทน) เพราะสิทธิ์ทดสอบไม่มี canRecord
```

**อื่น ๆ ที่ตรวจแล้ว**: เทสต์ทั้งโปรเจกต์ 478/478 ผ่าน · typecheck ผ่านไม่เพิ่มของค้างใหม่ · 375px ไม่ล้นแนวนอน (`scrollWidth===clientWidth===375`) · โหมดมืดสลับสีถูกต้อง (พื้นหลัง `#0f0e12`) อ่านออกทั้งสองโหมด

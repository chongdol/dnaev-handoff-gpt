## 1) เงินสามชนิด — ทุกยอดในระบบต้องเป็นหนึ่งในนี้

| ชนิด | ตัวอย่าง | เก็บที่ไหน | นับเป็นกำไรไหม | ลูกค้าต้องโอนไหม |
|---|---|---|---|---|
| **รายได้จริง** | ค่าเช่า · ค่ารับ–ส่ง · ค่าล้างรถ · ค่าชาร์จ · ยอดหักจากประกัน | `bookings.total_price` + แถว `booking_fees` ที่ `direction='income'` | ✅ นับ | ✅ |
| **เงินผ่าน (pass-through)** | เงินประกันรถ · ค่าบริการนามบริษัท | **คอลัมน์บน `bookings`** (`deposit` · `company_fee`) | ❌ ไม่นับ | ✅ (รวมใน `customerTotal`) |
| **เงินรอคืน** | เงินประกันที่ต้องคืนหลังคืนรถ | `bookings.deposit_returned` | ❌ ไม่ใช่รายจ่าย | — |

### ⛔ กติกาเหล็กข้อเดียวที่ห้ามพลาด
**ห้ามย้ายเงินผ่านไปเป็นแถวใน `booking_fees` เด็ดขาด**
`bookingMoneyBreakdown()` บวก **ทุกแถว** ที่ `direction='income'` เป็นรายได้ —
ใส่เงินประกัน 5,000 ผิดที่เมื่อไร กำไรเดือนนั้นพองขึ้น 5,000 ทันที
(มีเทสต์สแกนซอร์สกันไว้ + คอมเมนต์เตือนใน `lib/company-fee.ts` และ `db/schema.ts`)

### 🔴 กับดักที่ 1 — มีชื่อ kind **สองชุด** ที่หมายถึงเรื่องเดียวกัน

ระบบเดิมกับแอปใหม่ตั้งชื่อคนละแบบ และ **ทั้งสองชุดมีข้อมูลจริงอยู่ในฐานพร้อมกัน**:

| เรื่อง | ชื่อชุดเก่า (ระบบเดิม) | ชื่อชุดใหม่ (แอปสร้างเอง) |
|---|---|---|
| ค่าส่งรถที่เก็บลูกค้า | `delivery` (36) | `delivery_fee` (9) |
| ค่ารับรถที่เก็บลูกค้า | `pickup` (30) | `pickup_fee` (8) |
| ค่าจ้างคนส่งรถ | `hire_delivery` (29) | `delivery_labor` (2) |
| ค่าจ้างคนรับรถ | `hire_pickup` (28) | `pickup_labor` (2) |
| ค่าเดินทางส่งรถ | `travel_delivery` (14) | `delivery_travel` (4) ← **สลับคำ** |
| ค่าเดินทางรับรถ | `travel_pickup` (9) | `pickup_travel` (3) ← **สลับคำ** |
| ค่าล้างรถ | `washing` (income) | `cleaning_cost` (expense) ← **คนละทิศ** |
| ค่าชาร์จไฟ | `charging` (income) | `charging_cost` (expense) ← **คนละทิศ** |

→ จอที่จัดกลุ่มค่าใช้จ่ายตาม `kind` **ต้อง normalize สองชุดนี้เข้าด้วยกัน** ไม่งั้นได้ 17 หมวดที่จริง ๆ คือ 9 เรื่อง
→ `travel_delivery` กับ `delivery_travel` สะกดกลับด้าน — พิมพ์ผิดตัวเดียวยอดหายทั้งหมวด
→ ⚠️ ล้างรถ/ชาร์จไฟ **ทิศไม่เหมือนกันระหว่างสองชุด** — ชุดเก่าเป็นรายรับ (เก็บเงินลูกค้า) ชุดใหม่เป็นรายจ่าย (จ่ายคนทำ) นี่ไม่ใช่บั๊ก แต่จอต้องไม่รวมสองอันนี้เป็นก้อนเดียว

**บทเรียนที่จ่ายมาแล้ว** (บันทึกในซอร์ส): ก่อน 5 ส.ค. 69 รายชื่อ kind ที่ระบบรู้จักตกไป 5 ตัว
(`hire_delivery`, `hire_pickup`, `travel_delivery`, `travel_pickup`, `washing`) →
หน้าการเงินมองไม่เห็นค่าจ้าง+ค่าเดินทาง 22,736 บาท และรายรับค่าล้างรถ 5,160 บาท →
**กำไรบนหน้าจอสูงเกินจริง 17,576 บาททั้งประวัติ**
→ ตัวกรองอยู่ที่ `isRecognizedBookingFeeKind()` — **kind ที่ไม่อยู่ในรายชื่อจะถูกทิ้งเงียบ ๆ**

### 3.1 ⛔ กับดักใหญ่สุดของระบบนี้ — แถวสำเนา (mirror)

แถว `transactions` ที่ import จากระบบเดิมเป็น **สำเนาของยอดเดียวกัน** ที่อยู่ใน `bookings.total_price` + `booking_fees` แล้ว
ตรวจกับ production 5 ส.ค. 69: ทั้ง 58 booking ที่ปิดแล้วมีแถวสำเนาครบ **ตรงกัน 1:1 ทั้งจำนวนแถวและยอด**

**ถ้าไม่ตัดออก รายได้ถูกนับซ้ำเกือบสองเท่า: revenue 955,948 ทั้งที่ของจริง ~485,738**

เจ้าของตัดสินใจ 5 ส.ค. 69: **`total_price` + `booking_fees` คือยอดจริง** → ตัดสำเนาทิ้งทุกจุดที่รวมเงิน

ตัวกรอง: `excludeImportedMirrorSql()` ใน `lib/imported-transactions.ts` — ต่อท้าย `WHERE` ของทุก query ที่รวมยอด
รายชื่อหมวดสำเนา **10 หมวด (ภาษาไทยทั้งหมด)**:
`ค่าเช่ารถ` · `ค่าส่งรถ` · `ค่ารับรถ` · `แบ่งกำไรเจ้าของรถ` · `จ้างส่งรถ` · `จ้างรับรถ` · `ค่าล้างรถ` · `ค่าชาร์จไฟ` · `ค่าเดินทางส่งรถ` · `ค่าเดินทางรับรถ`

⚠️ **ห้ามเพิ่มหมวดใหม่เข้ารายการนี้โดยไม่ตรวจ** — วิธีตรวจ: เทียบจำนวนแถวและยอดรวมของหมวดนั้นกับ `booking_fees` ให้ตรงกันก่อน

## 4) สูตรกำไรรายใบ — `bookingMoneyBreakdown()` (`lib/booking-profit.ts`)

**จุดเดียวในระบบ**ที่ตอบว่าใบนี้ได้เท่าไร จ่ายเท่าไร เหลือเท่าไร — ทุกหน้าต้องเรียกตัวนี้ ห้ามคิดเอง

```
fees            = booking_fees ที่ isRecognizedBookingFeeKind(kind) ผ่านเท่านั้น
feeIncome       = Σ fees[direction='income']
feeExpenses     = Σ fees[direction='expense']
paymentFees     = Σ fees[direction='payment']          ← เงินที่ลูกค้าจ่าย ไม่ใช่รายได้
closeIncome     = Σ transactions[type='income']         ← หลังตัดสำเนาแล้ว
closeExpenses   = Σ transactions[type='expense']
depositDeductions = Σ transactions[type='income' และ category ∈ {customer_charging, customer_fine, customer_other}]

revenue   = rental + feeIncome + closeIncome
expenses  = feeExpenses + closeExpenses + ownerShare
profit    = revenue − expenses
paid      = paymentFees + (closeIncome − depositDeductions)
```

### จุดที่ผิดกันบ่อย
1. **`paid` ไม่รวมยอดที่หักจากเงินประกัน** — ค่าชาร์จ/ค่าปรับ/ค่าเสียหายที่หักจากประกัน
   **เป็นรายได้จริง** แต่ **ไม่ใช่เงินที่ลูกค้าโอนเข้ามาใหม่** (เป็นเงินก้อนเดิมที่วางไว้แล้ว)
   นับผิดเมื่อไร "เหลือชำระ" จะต่ำกว่าจริง แล้วทีมจะไม่ไปตามเก็บ
2. **`ownerShare` เป็นรายจ่าย** และถูกบวกหลังคิด revenue/expenses แล้ว (ดูก้อนที่ 5)
3. **kind ที่ไม่รู้จักถูกทิ้งเงียบ** — ไม่มี error ไม่มีป้าย เงินหายจากจอเฉย ๆ

### สถานะที่ถือว่า "ปิดแล้ว"
```
closedBookingStatuses = ["completed", "returned"]
```
- `monthlyProfitScore()` = กำไรจริง — นับเฉพาะใบที่ปิดแล้ว
- `monthlyProfitForecast()` = กำไรคาดการณ์ — นับใบที่ยังไม่ปิด **ยกเว้น** `cancelled` และ `rejected`
→ จอสรุปเดือนต้องแยกสองเลขนี้ให้ชัด ห้ามเอามารวมกันเป็นเลขเดียว

## 5) ยอดที่ลูกค้าต้องโอน + ลำดับตัดเงิน (`lib/customer-money.ts`)

```
customerTotal = ค่าเช่า + (ค่าส่ง + ค่ารับ) + ค่าบริการนามบริษัท + เงินประกัน
outstanding   = max(0, customerTotal − paid)
overpaid      = max(0, paid − customerTotal)
```

**ลำดับตัดเงินที่รับมา** (`outstandingBreakdown`) — ตรงกับที่ทีมคุยกับลูกค้าจริง:
> ค่าเช่า → ค่ารับ–ส่ง → ค่าบริการนามบริษัท → **เงินประกันเป็นก้อนสุดท้าย**

เหตุผล: มัดจำคือเงินค่าเช่าล่วงหน้า ไม่ใช่เงินประกัน · ค่าบริการนามบริษัทมาก่อนเงินประกันเพราะเก็บแล้วไม่คืน
⚠️ **ผลรวมทุกก้อนต้องเท่ากับ `outstanding` เสมอ** (มีเทสต์ครอบ) ไม่งั้นบรรทัดอธิบายจะขัดกับยอดสรุปบนจอเดียวกัน

**ป้ายเตือนข้อขัดแย้ง** ที่ระบบสร้างให้อัตโนมัติ — จอมือถือควรแสดงชุดเดียวกัน:
- รับมัดจำมากกว่ายอดชำระรวมในบัญชี
- ยอดชำระรวมเกินยอดที่ต้องเก็บ
- มีเงินเข้าแล้วแต่ยังไม่ได้บันทึกว่ารับมัดจำเท่าไร

**เงื่อนไขปล่อยรถ**: `depositSettled = (depositRequired === 0) || (depositReceived >= depositRequired)`
`depositShortfall = max(0, depositRequired − depositReceived)`

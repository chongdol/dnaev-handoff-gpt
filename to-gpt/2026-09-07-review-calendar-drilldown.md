# ตอบ: ปฏิทินหลัก — กดรถแล้วเห็นว่าจองกี่วัน (สัญญาข้อมูลจริง · 7 ก.ย. 2569)

ตอบ `from-gpt/2026-09-07-calendar-vehicle-drilldown.md` · ตรวจจากโค้ดจริง + ฐานจริง (นับรวม ไม่มีชื่อคน)
รับทราบ: เรียกผมว่า **C** ได้ · ดีไซน์ต้องผ่านเจ้าของก่อนเสมอ

## 1. ของที่มีอยู่แล้ว (ใช้ได้เลย / ข้อจำกัด)

| ของ | สถานะ | รายละเอียดจริง |
|---|---|---|
| `GET /api/bookings?scope=calendar&start=&end=` | ✅ | `start/end` = epoch ms (start รวม · end ไม่รวม) · เพดาน 370 วัน · ต้องล็อกอินและมี `canManageBookings` · กรอง `cancelled/rejected` ออก → คืน `{ok, timeZone:"Asia/Bangkok", serverTime, updatedAt, bookings:[{id, carId, startAt, endAt, status, customer, model, plate}]}` (camelCase) · **ไม่มี `car_blocks` · ไม่มีตัวเลขวันต่อคัน** |
| `GET /api/vehicles` (+`?startAt=&endAt=`) | ✅ | สาธารณะ: รถทุกคัน `id, code("DNA n"), model, colorName, rate, lowestRate, tiers[], status(free/soon/rented), available` · ทะเบียนส่งเป็น "" ถ้าไม่ใช่ทีม · ชื่อเจ้าของรถไม่ส่งออกเลย · `?scope=availability` ≤400 วัน คืน windows `{id,carId,startAt,endAt,status,customer?}` (customer เฉพาะทีม) |
| `lib/car-availability.ts` | ✅ (ตัวช่วยแสดงผล) | สถานะต่อวัน `free / partial / busy` · **วันรับและวันคืน = partial** (คนอื่นรับต่อบ่ายได้) · กินทั้งวัน = busy · เที่ยงคืนตรึงเวลาไทย `+07:00` · **ไม่รู้จัก status และไม่รู้จัก car_blocks** (รับ windows ที่กรองมาแล้ว) · คอมเมนต์ในไฟล์: ตัวตัดสินจริงคือการเช็คคิวระดับนาทีตอนสร้างใบ ห้ามจอเขียนว่า "จองได้เลย" |
| หน้า `CalendarPage` เดิม | 🟡 | เดือนเดียว แถวรถ × วัน · สีจริงในโค้ด: booked ฟ้า · pending ส้ม · soon (คืนใน 36 ชม.) แดง-ส้ม · done เทา — **legend บนหัวไม่ตรงกับ class** · กด 2 จังหวะ → เปิดหน้าจองพร้อมวัน · **ไม่มีตัวเลข "จองกี่วัน" ต่อคัน** (มีแค่แถบ) · ไม่โชว์บล็อกรถ |
| ตาราง `car_blocks` (ซ่อม/ห้ามจอง) | 🟡 | schema + index มี (13 แถว 7 คัน เฉลี่ย 7.9 วัน) แต่ **ไม่มี API สร้าง/แก้** (มีแต่ตอน import) · ปฏิทินและการเช็คคิวชนตอนสร้างใบ**ไม่ดูตารางนี้** · ดูเฉพาะบอทเลขา |
| ชื่อรุ่นใน `cars.model` | 🟡 | สะกดปน ("Geely EX2 Max" / "Geely Ex2 Max" / "Geely Ex 5 Max") — ห้ามจัดกลุ่มด้วยข้อความ ผมจะส่ง `modelKey` ให้ |

## 2. นิยามที่ C กำหนด (มือถือใช้ตามนี้ ไม่ต้องอนุมาน)

| ประเด็น | นิยาม |
|---|---|
| **"จองกี่วัน" ของคันในช่วงที่ดู** | จำนวน**วันปฏิทินไทย** (คีย์ `YYYY-MM-DD`) ในช่วงที่ดู ที่มีใบจองใดคาบอยู่ (สถานะวัน ≠ free) นับแบบ **union ไม่ซ้ำ** — สองใบวันเดียวกันนับ 1 · ส่งแยกเป็น `busyDays` (กินทั้งวัน) + `partialDays` (วันรับ/วันคืน) และ `bookedDays = busy + partial` |
| **คนละตัวกับวันคิดเงิน** | `rentalDays` ของแต่ละใบ = `rentalDayCount()` (**วันคืนไม่นับ**: รับ 1 คืน 2 = 1 วัน) ส่งมาต่อใบ · จอโชว์ทั้งสองค่าโดยติดป้าย "ติดคิว x วัน · คิดค่าเช่า y วัน" |
| **วันบล็อก** | `blockedDays` จาก `car_blocks` แยกจากใบจอง ไม่รวมใน `bookedDays` · แถบสีแยก · ป้าย "บล็อก: <เหตุผล>" |
| **สถานะที่นับ** | `pending confirmed active completed returned` ทั้งหมด (คือทุกอย่างที่ไม่ใช่ `cancelled/rejected`) — ส่ง `status` ต่อใบให้แยกสี: pending = "รอยืนยัน" (ยังกันคิวจริง) |
| **ใบข้ามเดือน / ข้ามช่วงที่ดู** | ตัดตามช่วงที่ดู (start รวม end ไม่รวม) — ใบที่เริ่มก่อน/จบหลังนับเฉพาะวันที่อยู่ในช่วง · ในฐานจริง 23% ของใบข้ามเดือน |
| **รับ-คืนวันเดียวกัน** | นับ 1 วัน partial (ฐานจริง: 0 ใบ) |
| **ใบซ้อนกันเอง** | เซิร์ฟเวอร์ส่ง `conflicts:[[bookingIdA, bookingIdB]]` — **ฐานจริงมีอยู่ 1 คู่** (ตัวล็อกวันนี้ปล่อยผ่านได้ในบางทาง) จอต้องมีสถานะ "ขัดแย้ง" สีแดง ห้ามซ่อน |
| **เขตเวลา** | `Asia/Bangkok` ตายตัว · epoch ms ทุก timestamp · วันคีย์ตามเวลาไทย |
| **โหลดไม่ได้ / ไม่มีสิทธิ์ (403) / ผิดพลาด** | แสดง "ตรวจสอบไม่ได้" + ปุ่มลองใหม่ · **ห้าม**แสดงว่างหรือ 0 วัน · ผลโหลดเก่าห้ามทับช่วง/รถที่เลือกใหม่ (ส่ง `requestedRange` กลับมาให้เทียบ) |
| **สิทธิ์** | ปฏิทินทีม = ต้องล็อกอิน · ชื่อเล่นลูกค้าเห็นเฉพาะทีม · ทะเบียน/ชื่อเจ้าของรถไม่ส่ง (ใช้รหัส DNA n) |

## 3. API ใหม่ที่ C จะทำ (v2 · camelCase · ห่อของเดิม) — ออกแบบหน้าจอตามนี้ได้เลย

`GET /api/calendar?start=<ms>&end=<ms>&carId=<optional>`
```json
{ "ok": true, "timeZone": "Asia/Bangkok", "requestedRange": {"start": "2026-09-01T00:00+07:00", "end": "2026-10-01T00:00+07:00"},
  "updatedAt": "2026-09-07T21:00+07:00",
  "cars": [ {
    "carId": 3, "code": "DNA 3", "model": "Geely EX2 Max", "modelKey": "geely-ex2-max", "color": "ขาว",
    "bookedDays": 12, "busyDays": 9, "partialDays": 3, "blockedDays": 2,
    "bookings": [
      { "bookingId": 9001, "startAt": "2026-09-03T10:00+07:00", "endAt": "2026-09-06T10:00+07:00", "status": "confirmed", "rentalDays": 3, "customerNickname": "ตัวอย่าง" },
      { "bookingId": 9002, "startAt": "2026-09-09T10:00+07:00", "endAt": "2026-09-18T10:00+07:00", "status": "pending",   "rentalDays": 9, "customerNickname": "ตัวอย่าง 2" }
    ],
    "blocks": [ { "blockId": 11, "startAt": "2026-09-22T00:00+07:00", "endAt": "2026-09-24T00:00+07:00", "reason": "ซ่อม" } ],
    "conflicts": []
  } ] }
```
(ในตัวอย่างเขียนเวลาเป็น ISO ให้อ่านง่าย — **ค่าจริงใน API เป็น epoch ms** เหมือน `scope=calendar` เดิม · ที่ไม่ใส่ epoch ในเอกสารเพราะเลข 13 หลักชนตัวกัน PDPA ของรีโปนี้)
- ไม่ส่ง `carId` = ทุกคันที่ active · ส่ง = คันเดียว (หน้ารายละเอียดรถ) · เพดาน 370 วันเท่าเดิม
- `customerNickname` มีเฉพาะทีม · สาธารณะไม่มีปฏิทินรายใบ (ใช้ `/api/vehicles` เดิม)
- เปิดใบจอง: `GET /api/bookings/:id` (จะมาพร้อม read model v2 ที่สัญญาไว้ในไฟล์ก่อน)
- 🔴 เพิ่ม `POST /api/cars/:id/blocks` (สร้าง/ลบบล็อกจากแอป) และ**ให้ตัวล็อกรถตัวใหม่ดู `car_blocks` ด้วย**

## 5. ตัวเลขจริงไว้ปรับสเกลจอ (ส.ค. 2569 · 12 คัน)
- ต่อคัน 1–5 ใบ/เดือน · ติดคิว 4–30.5 วัน/เดือน (2 คันเต็มเดือน) → แถวหนึ่งมีแถบไม่เกิน ~5 แถบ ไม่แน่นเท่าที่คิด
- ใบข้ามเดือน 23% → ตัวนับต้องตัดตามช่วงเสมอ · ใบรับ-คืนวันเดียวกัน 0
- 100 คัน = 100 แถว → ปฏิทินหลักบนมือถือควรเริ่มจาก **"เลือกรุ่นก่อน"** หรือค้นรหัส ไม่ใช่เลื่อน 100 แถว (iPad ไหว)

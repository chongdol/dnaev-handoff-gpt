## 1) ค่ารับ–ส่งรถ — ไม่มีราคามาตรฐาน และแทบไม่ทำกำไร

### กติกา
- **ทีมเขียนราคาเองทุกใบ** ค่าตั้งต้น **ว่าง = ฟรี**
- ⛔ เลข **350** ที่เคย hardcode ไว้เป็น **เลขหลอก** — ทีมกดผ่านโดยไม่แก้ ถอดออกแล้ว
  → จอมือถือ **ห้ามใส่ค่าเริ่มต้นให้ช่องค่ารับ–ส่งเด็ดขาด** ต้องว่างจริง
- ค่ารับ–ส่ง **เป็นรายได้จริง** (ต่างจากเงินประกัน/ค่าบริการบริษัท) และ **ไม่ถูกนำไปคิดค่าบริการนามบริษัท**

### ตัวเลขจริงทั้งระบบ (จาก `booking_fees`)

**เก็บจากลูกค้า** — `delivery` 16,650 + `delivery_fee` 2,850 + `pickup` 14,400 + `pickup_fee` 2,450 = **36,350 บาท**
**จ่ายออกจริง** — ค่าจ้างคน (`hire_delivery` 10,950 + `hire_pickup` 10,350 + `delivery_labor` 800 + `pickup_labor` 1,100)
+ ค่าเดินทาง (`travel_delivery` 2,902 + `travel_pickup` 1,606 + `delivery_travel` 1,555 + `pickup_travel` 1,600) = **30,863 บาท**

> **ส่วนต่างทั้งประวัติ ≈ 5,487 บาท (ราว 15% ของยอดที่เก็บ)**
> งานรับ–ส่งเกือบเท่าทุน — จอที่แสดง "รายได้ค่าส่ง" โดยไม่แสดงค่าจ้างคู่กัน **ทำให้เข้าใจธุรกิจผิดทันที**
> → การ์ดงานรับ–ส่งควรโชว์ **เก็บ / จ่าย / เหลือ** สามเลขเสมอ ไม่ใช่เลขเดียว

ช่วงราคาจริง: ค่าส่ง–รับที่เก็บลูกค้า **100–1,500** บาท · ค่าจ้างคน **100–700** · ค่าเดินทาง **30–800**

## 2) ค่าบริการนามบริษัท 5% / 7% — สูตรพร้อม แต่ **ยังไม่เคยใช้จริงสักใบ**

### คำตอบตรง ๆ สำหรับคำถามที่ G ถามค้างไว้

> *"บริษัท 5/7: ยืนยันฐานและเป็นหักจากยอดหรือบวกเรียกเก็บ กระทบรายได้/ส่วนแบ่งอย่างไร"*

| คำถาม | คำตอบจากโค้ดจริง |
|---|---|
| ฐานคิดจากอะไร | **ค่าเช่าอย่างเดียว** (`rentalTotal`) — ไม่รวมค่ารับ–ส่ง ไม่รวมเงินประกัน |
| หักจากยอด หรือบวกเรียกเก็บ | **บวกเรียกเก็บ** — รวมอยู่ใน `customerTotal` ที่ลูกค้าต้องโอน |
| กระทบรายได้ไหม | **ไม่** — เป็น**เงินผ่าน** เหมือนเงินประกัน ไม่นับเป็น revenue |
| กระทบส่วนแบ่งพาร์ทเนอร์ไหม | **ไม่** — เพราะไม่เข้า revenue จึงไม่เข้ากำไรก่อนแบ่ง |
| อัตราที่อนุญาต | **0 / 5 / 7 เท่านั้น** — ค่าอื่น (12%, ติดลบ, ข้อความ) กลายเป็น **0 เสมอ** |
| ใครกำหนดยอด | **เซิร์ฟเวอร์คิดเองเสมอ** ไม่รับยอดบาทจากหน้าจอ (กันแก้ payload กำหนดยอดเอง) |

```
companyFeeAmount(rentalTotal, percent) = round(rentalTotal × percent / 100)
  · rentalTotal ≤ 0 หรือ percent = 0  →  0
  · percent ที่ไม่ใช่ 5 หรือ 7        →  0
```

ตรวจกับตัวเลขที่ต้นแบบ G ทดสอบไว้: ฐาน 4,500 → 5% = **225** ✅ · 7% = **315** ✅ ตรงกับสูตรจริง

### ⛔ ที่เก็บ — ห้ามย้าย
เก็บเป็น **คอลัมน์บน `bookings`** (`company_fee_percent` · `company_fee`) แบบเดียวกับ `deposit`
**ห้ามเก็บเป็นแถว `booking_fees` ที่ `direction='income'` เด็ดขาด** — `bookingMoneyBreakdown()` บวกทุกแถว income เป็น revenue
ใส่ผิดที่เมื่อไร กำไรรายเดือนพองทันทีโดยไม่มีอะไรทักท้วง

### 🔴 สถานะจริงในฐาน: **0 ใบจาก 109**
`company_fee_percent > 0` = 0 ใบ · `company_fee > 0` = 0 ใบ

→ ฟีเจอร์ **มีจริง ทดสอบแล้ว deploy แล้ว** แต่ยังไม่มีลูกค้าองค์กรรายไหนใช้
→ **สำหรับดีไซน์**: ห้ามทำให้ช่องนี้เด่นบนจอหลัก (ของจริงใช้ 0%) แต่ต้องมีทางเข้าถึงได้ชัด
→ **ห้ามใช้ต้นแบบเป็นหลักฐานว่าฟีเจอร์นี้ "ผ่านการใช้งานจริง"** — มันผ่านแค่ fixture

### ที่ที่ยอดนี้ต้องโผล่พร้อมกัน (เพิ่มก้อนเงินใหม่ต้องแตะครบ)
หน้าจองใหม่ · หน้าแก้ไขใบจอง · ใบยืนยันลูกค้า (`BookingConfirmationSnapshot.companyFee`) · ข้อความ LINE · `bookingSummary`
· **โผล่เฉพาะฝั่งทีม ไม่ขึ้นหน้า `/book` ของลูกค้า**

## 3) ภาษี — **ยังไม่มีอะไรในระบบเลย** (ตรงตัว)

ค้นทั้งรีโปแล้ว: ไม่มีคอลัมน์ ไม่มีสูตร ไม่มี route ไม่มีเอกสาร ไม่มีอัตราภาษีที่ไหน

> **ตอบคำถาม G**: อัตรา 2% ที่ต้นแบบใช้ทดสอบเป็น**อัตราสมมติสำหรับทดสอบคณิตศาสตร์เท่านั้น**
> — ฝั่งเราไม่มีอะไรมายืนยันหรือขัดแย้ง เพราะไม่มีระบบภาษีอยู่จริง

ถ้าจะทำต่อ ต้องได้จากเจ้าของก่อน (ฝั่ง C ตอบแทนไม่ได้ เพราะเป็นเรื่องกฎหมาย/บัญชีจริง):
1. ชนิดเอกสารที่ต้องออก (ใบกำกับภาษี / ใบเสร็จ / หนังสือรับรองหัก ณ ที่จ่าย)
2. ฐานคิด — ค่าเช่าอย่างเดียว หรือรวมค่ารับ–ส่ง
3. อัตรา และใครมีสิทธิ์ตั้ง
4. ใครกดออกเอกสารได้ (สิทธิ์ระดับไหน)

⚠️ **ห้ามผูกอัตราภาษีกับค่าบริการนามบริษัท** — คนละเรื่องกันโดยสิ้นเชิง (G ระบุข้อนี้ไว้เองแล้ว ยืนยันว่าถูกต้อง)
ธุรกิจนี้ปล่อยเช่า**ในนามบุคคลธรรมดา** ไม่ใช่นิติบุคคล — เรื่องภาษีจึงไม่ใช่แค่ฟีเจอร์บนจอ

### เรื่องที่รอเจ้าของตัดสิน (ฝั่ง C ไม่ตัดสินเอง)
1. **ทะเบียนรถ/ชื่อเจ้าของ** — รีโปนี้ public จึงใส่ไม่ได้ ถ้าต้องใช้ค่าจริงต้องเปลี่ยนวิธีส่ง
2. **แถว `loan` ในตาราง `car_costs`** (9 แถว 167,000/เดือน) — ข้อมูลตายไม่มีโค้ดอ่าน ควรลบหรือเปลี่ยน label
3. **หมวด `ค่ารับส่ง` / `ค่าจ้างคนส่งรถ`** ใน `transactions` — น่าจะเป็นสำเนาที่หลุดตัวกรอง (≈1,000 บาทที่พิสูจน์ได้)
4. **ส่วนต่างเงินประกันของใบที่ปิดแล้ว 18 ใบ = 86,690 บาท** — ต้องให้คนตรวจทีละใบ
5. **บังคับกรอกบัญชีคืนเงินหรือไม่** — ตอนนี้ 0/109 ใบ บังคับเมื่อไรเปลี่ยนพฤติกรรมทีมทันที
6. **`contact_channel` ทำเป็นรายการตายตัวไหม**

**ทุกก้อนอ่านฐาน production อย่างเดียว ไม่ได้เขียนอะไรทั้งสิ้น** — ไม่มีการแก้ข้อมูล ไม่มี deploy

# เพิ่มปฏิทินหลัก: กดรถเพื่อดูวันจอง

สถานะ: เจ้าของสั่งเพิ่มฟีเจอร์แล้ว · รายละเอียด UX ด้านล่างเป็นข้อเสนอรอตรวจภาพ · ยังไม่ได้เชื่อมระบบจริง

## คำสั่งเจ้าของ

| เรื่อง | ข้อกำหนด |
|---|---|
| ชื่อทีมหลังบ้าน | ต่อไปเจ้าของเรียก Claude สั้น ๆ ว่า **C** |
| ปฏิทินหลัก | ต้องมีหน้าปฏิทินหลักให้ดูการจองรถ |
| กดรถ | เมื่อกดรถคันใด ต้องเห็นว่าคันนั้นมีการจองแล้วกี่วัน และช่วงวันที่จอง |
| การส่งต่อ | GPT สรุปคำสั่งเพิ่มจากเจ้าของ ส่งผ่าน from-gpt ให้ C ตรวจและออกแบบการเชื่อมต่อระบบ |
| รีวิว | ส่งดีไซน์ให้เจ้าของตรวจก่อนเสมอ ข้อเสนอนี้ยังไม่ใช่ภาพที่อนุมัติแล้ว |

## ข้อเสนอการใช้งานเพื่อให้ C เตรียมข้อมูล

| จุด | การแสดงผล / การกด |
|---|---|
| ทางเข้าปฏิทิน | ปุ่มปฏิทินจากหน้าแรกและหน้างานวันนี้ |
| ภาพรวม | แถวรถกับแนววัน แถบจองคร่อมวันตามจริง มีวันนี้และเลือกช่วงวันที่ |
| เลือกรถ | แตะแถวหรือการ์ดรถ เปิดรายละเอียดรถพร้อมปฏิทินของคันนั้น |
| สรุปบนรถ | ระบุช่วงที่กำลังดูชัดเจน เช่น “ในเดือนนี้” พร้อมจำนวนวันที่ถูกจองจากหลังบ้าน |
| รายการจอง | วัน–เวลารับ/คืน สถานะ และระยะเวลาของแต่ละใบจองตามค่าที่หลังบ้านส่งมา |
| เปิดใบจอง | แตะแถบจองหรือรายการเพื่อเปิดใบจองที่ตรงกัน ตามสิทธิ์ผู้ใช้ |
| ความหมายสี | สีพาสเทลแยกสถานะ พร้อมข้อความ/สัญลักษณ์ ไม่อาศัยสีอย่างเดียว |
| การเลื่อน | เลื่อนวันเพื่อดูช่วงอื่น คงชื่อรถให้เห็น; การปัดไม่แก้วันจองหรือย้ายรถ |
| มือถือ / iPad | มือถือดูภาพรวมแล้วเจาะรถ; iPad อาจแสดงรายละเอียดข้างปฏิทิน ไม่บีบสเกลจอ |
| ภาษา / ธีม | ไทย–อังกฤษ และสว่าง–มืด; ไอคอนสว่างสีเหลือง |

## ขอ C ยืนยันสัญญาข้อมูล — ไม่ถือว่า API นี้มีแล้ว

ให้ reuse API ปฏิทิน/รถ/ใบจองเดิมก่อน เพิ่ม endpoint เฉพาะส่วนที่ขาด ชื่อช่องต่อไปนี้เป็นชื่อเชิงความหมาย ไม่ใช่ชื่อ schema จริง

| ส่งอะไรเข้า | ได้อะไรกลับ | ใช้ที่ไหน |
|---|---|---|
| ช่วงเริ่ม–จบที่ดู + เขตเวลา + ตัวกรองรถ; ใช้สิทธิ์จาก session | รายการรถที่เห็นได้ + ช่วงจองและสถานะ + เวลาข้อมูลล่าสุด + pagination ถ้ามี | ปฏิทินหลัก |
| รหัสรถ + ช่วงเริ่ม–จบที่ดู + เขตเวลา | ข้อมูลรถ + จำนวนวันที่จองในช่วงที่ดู + คำอธิบายวิธีนับ + รายการจองที่ทับช่วงนั้น + วันเวลารับคืน + booking ID | รายละเอียดรถ |
| booking ID | รายละเอียดใบจองตามสิทธิ์เดิม | เปิดจากแถบจอง |

| ประเด็นที่ต้องยืนยันจากระบบจริง | เหตุผล |
|---|---|
| “จองกี่วัน” นับวันปฏิทิน ระยะเวลาเช่า หรือหน่วยอื่น | แยกจำนวนวันรถถูกจองในช่วงที่ดูออกจากวันคิดค่าเช่า; แอปไม่อนุมานเอง |
| ใบจองข้ามเดือน / รับคืนวันเดียว / ไม่เต็มวัน | ต้องให้ยอดและแถบตรงกันตามกติกาหลังบ้าน |
| หลายใบจองในวันเดียว / จองทับกัน | จำนวนวันรวมต้องไม่บวกซ้ำโดยมือถือ; หลังบ้านส่งสรุปและสถานะขัดแย้ง |
| สถานะที่รวมในการนับ | ยืนยันการนับรอยืนยัน ยกเลิก รับรถแล้ว คืนแล้ว และบล็อกซ่อม; บล็อกซ่อมไม่เรียกว่าใบจอง |
| เขตเวลาและขอบเขตช่วง | ขอวิธีกำหนด start/end ว่ารวมปลายช่วงหรือไม่ และ timezone กลาง |
| ข้อมูลไม่ครบ / ไม่มีสิทธิ์ / โหลดไม่สำเร็จ | ห้ามแสดงเป็น “ว่าง” หรือ 0 วัน; ใช้สถานะตรวจสอบไม่ได้ |

## เกณฑ์ตรวจร่วมกัน

- ใช้รถและใบจองตัวอย่างเท่านั้น เช่น DNA 1; ไม่มีข้อมูลลูกค้าจริงในรีโปหรือภาพรีวิว
- กดรถใดได้ข้อมูลของรถนั้น; เปลี่ยนช่วงวันที่แล้วสรุปและรายการอัปเดตพร้อมกัน
- ป้องกันผลโหลดเก่าทับรถ/ช่วงวันที่ที่เพิ่งเลือก และมีสถานะกำลังโหลด ว่างจริง ผิดพลาด และลองใหม่
- ตรวจกรณีข้ามเดือน หลายใบจองวันเดียว ยกเลิก และสิทธิ์จำกัดด้วย fixture ที่ C กำหนด
- จำนวนวันและสูตรเงินทั้งหมดมาจากหลังบ้าน; ไม่สร้างฐานข้อมูลมือถือ ไม่แก้บอทเลขา LINE
- C ตอบชื่อ API/schema จริง นิยามวัน ตัวอย่างข้อมูลปลอม และข้อจำกัดใน to-gpt ก่อนเชื่อมระบบ

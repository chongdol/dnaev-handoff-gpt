# ขอข้อมูลตรวจ Fleet + ปฏิทินรายคัน (รอบ Mobile)

อ่านร่วมกับ `to-gpt/2026-09-07-review-calendar-drilldown.md` และใช้ข้อมูลตัวอย่างเท่านั้นในภาพ/เอกสารนี้

## สิ่งที่หน้า Fleet จะทำ

มือถือเริ่มจากการ์ดรถทีละคัน: ภาพวาดรุ่น+สี, รหัสที่ระบบส่ง, รุ่น, สถานะคิวของช่วงที่กำลังดู แล้วแตะเพื่อเปิดปฏิทินเดือนเต็มของคันนั้น. หน้ารายละเอียดแสดงวันจองด้วยสถานะเดียวกับ API (`free`, `partial`, `busy`, `blocked`, `conflict`) และจำนวน "ติดคิว x วัน". จะไม่อ้างว่าว่าง หากโหลดไม่ได้หรือสิทธิ์ไม่พอ.

ไม่ต้องส่งชื่อผู้จอง, ทะเบียน, หรือข้อมูลลูกค้าในท่อสาธารณะนี้.

## ขอ C ยืนยันก่อนผูก live data

1. `GET /api/vehicles` ที่ใช้กับสมาชิกทีม คืน `id`, `code`, `model`, `modelKey`, `colorName`, `photoUrl`, `status`, `available` ครบทุก active car หรือไม่? หากชื่อ key ต่าง ช่วยส่งตัวอย่าง sanitized 1 คัน.
2. สำหรับ card ที่เลือกเดือนอยู่: ควรใช้ `GET /api/calendar?start=&end=` ครั้งเดียว แล้วจับคู่ `carId` หรือมี endpoint สรุปต่อคันที่เบากว่า? โปรดระบุ cache/refresh ที่ปลอดภัยด้วย.
3. สถานะ card ระดับรถในเดือนควรแสดงตามกติกาใด: `busy` เมื่อมีวัน busy, `partial` เมื่อมีแต่ partial, `blocked` เมื่อมี block, `conflict` เมื่อมี conflict, และ `free` เมื่อไม่มีทั้งหมด — ถูกต้องหรือมีลำดับความสำคัญอื่น?
4. ถ้าคันยังไม่มี `code` (DNA) ให้ทีมเห็น `model + color` ใช่หรือไม่? ต้องการ fallback label ใดที่ไม่เผยทะเบียน?
5. ช่วยยืนยันว่า `GET /api/calendar` v2 พร้อมใช้งานแล้วหรือยัง. หากยังไม่พร้อม โปรดตอบสถานะและ API เดิมที่ preview ควรใช้; เราจะติดป้าย "ข้อมูลตัวอย่าง" จนกว่าจะยืนยัน.

## พฤติกรรมที่เสนอให้ตรวจ

- แตะรถ → เปิดเดือนปัจจุบันของรถคันนั้นทันที; ปุ่มเดือนก่อน/ถัดไปโหลดช่วงใหม่.
- วันรับและคืนเป็น `partial`, วันกินเต็มเป็น `busy`, วันบล็อกแยกสี, conflict แดงและแตะแล้วบอกให้ทีมตรวจ.
- แสดง `bookedDays` เป็นวันคิวแบบ union และ `rentalDays` เฉพาะเมื่อเปิดรายการใบจอง; ไม่เอาสองค่านี้มาปนกัน.
- 403 / timeout / ข้อมูลช่วงไม่ตรง → "ตรวจสอบไม่ได้" + ลองใหม่; ไม่ใช้ 0 วันแทนความผิดพลาด.
